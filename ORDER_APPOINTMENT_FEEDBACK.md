# Inline appointment feedback

The Add/Edit Signing form and screenshot review share inline appointment feedback. The existing form values remain in SwiftUI state throughout checking and while the conflicting order opens in a separate details sheet.

## Scheduling parity

`OrderScheduleRules` mirrors the web app's `App.jsx` functions `getOrderDateTimeTimestamp` and `getOrderScheduleOverlap`:

- The nearest signing whose **start time is within 120 minutes**, inclusive, produces a warning. This is a proximity rule; it does not infer an appointment end time.
- The order being edited is excluded. The web app has no status exclusions, so Paid and Cancelled signings remain candidates.
- The shared data model has no appointment duration. No duration field, default duration, or new server constraint is introduced.
- Local warnings permit saving, matching the web app. A server-rejected submission remains rejected and shows its schedule message inline.

Existing orders are interpreted in the device's current local time zone, matching the browser's local zone. Offset-bearing timestamps are converted to that zone before using calendar components. Date-only form values remain calendar dates. Explicit midnight is distinct from an absent time; web normalization treats an inferred local midnight as untimed.

The form checks its current cached schedule immediately, refreshes account-scoped orders on opening, and fetches fresh orders before submission. A failed refresh shows a retry message and preserves the draft. Scheduling feedback always uses the current appointment, even if a previous request finishes later. Superseded and previous-account requests are ignored.

`OrderValidationFailure` recognizes structured schedule field errors and `SCHEDULE_CONFLICT`, `ORDER_SCHEDULE_CONFLICT`, `SCHEDULING_CONFLICT`, and `APPOINTMENT_CONFLICT` error codes. An optional `conflictingOrderId` enables the details action when that order is in the owned order list. Other conflict codes, such as invoice-number conflicts, retain their normal handling. The current backend does not expose a separate schedule-validation endpoint or enforce the proximity warning atomically; existing order endpoints are reused without backend changes.

## One rescission calculation

`RescissionRules` is used by both the inline read-only Estimated rescission date and the standalone calculator. It mirrors `getRescissionEstimate` in web `App.jsx` and `calculateRescissionDeadline` / `isFederalHoliday` in `src/utils/notary.js`.

- The rescission section is shown only for Refinance and HELOC; it is hidden when the type is blank or any other signing type is selected.
- Count three days after the signing date; Saturdays count, Sundays and observed federal holidays do not.
- Include moving holidays and fixed holidays observed on adjacent weekdays, including cross-year observations.
- Use Gregorian calendar-day arithmetic rather than adding 24-hour intervals, preserving dates across time zones and DST.
- For an eligible type, explain missing or invalid signing dates instead of assuming a deadline. The existing schema has no rescission override or persisted rescission field, so the estimate is read-only and no manual override is offered.

The old calculator-only holiday list and optional Saturday rule were removed to prevent the two iOS screens from producing different results.

## Validation

Focused tests cover resolved conflicts, the inclusive boundary, nearest-order selection, editing exclusions, existing status behavior, missing time, cross-midnight appointments, local conversion of UTC/offset timestamps, DST, stale responses, account changes, retry, and structured server failures. UI tests exercise opening conflict details without losing draft fields, clearing the time to resolve a warning, inline server errors, corrected retry, and saving with a nonblocking local warning. Layout captures cover normal and larger text on several iPhone widths.

The checked-in test fixture was generated by executing the actual web functions: 342 rescission cases and 56 schedule cases across Los Angeles, New York, UTC, and Kiritimati. Its metadata records source hashes. Regenerate when the web rules change:

```sh
node scripts/generate-order-rule-fixtures.mjs /path/to/notary-web-app
```
