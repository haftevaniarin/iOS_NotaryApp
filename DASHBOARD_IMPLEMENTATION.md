# Dashboard

The SwiftUI screen supports iOS 17+. `Features/Dashboard` contains the observable view model, repository protocol, in-memory/mock implementations, preview data, and the five requested components. `Models/DashboardModels.swift` defines the new Decimal-based models. `DesignSystem/Theme.swift` contains semantic Dashboard colors and Dynamic Type fonts while preserving the existing billing tokens/styles. The bundled Fraunces and IBM Plex Sans static files already provide weights 400/500/600 and remain registered in `NotaryLedger-Info.plist`.

`Features/Navigation/LedgerAppShell.swift` supplies a native four-tab `TabView` (Home, Signings, Accounting, Menu). Home has no custom status bar or legacy navy header. Existing signing creation stays available in Signings; invoice/expense/customer/report pages are under Accounting, and account/legal/admin pages are under Menu, with Profile first and Billing second. Customers is available only in Accounting. Switching bottom tabs resets Accounting and Menu to their main lists; explicit protected URLs still open their requested destinations. Search text clears when leaving Signings, Customers, or Expenses. Existing protected URLs route to the matching tab and navigation path. Authentication and backend billing rules were not changed.

## Data boundary

`DashboardRepository.load()` is the async boundary for a future Dashboard API. `InMemoryDashboardRepository` can load an immutable snapshot or a current in-memory source; `MockDashboardRepository` supports both successful and failing responses. Ordinary failures surface a retry state, canceled refreshes retain prior state, and superseded responses cannot replace newer data. Pull to refresh reloads the repository.

The production host reads the ledger that AppState has already loaded. Credential notifications load through the existing authenticated credentials API and share the Profile editor model. They refresh when Home appears, the app becomes active, or the user pulls to refresh; unsaved credential edits are preserved. Saved renewals and removals immediately update the notification list and bell badge. Expiry status recalculates every minute while visible, using the same local calendar-day and one-calendar-month boundary as Profile. Account changes clear saved credentials and reject late responses from the previous account. Synthetic values are isolated in `PreviewData` and explicit debug UI fixtures; production account totals never use the sample snapshot. The preview collection covers loaded, empty, loading, error, and AX3.

Currency values in the new models, calculations, and presentation use Decimal and currency FormatStyle. The compatibility adapter converts the existing legacy Double fields through their decimal string representation before calculating; the old backend/data models are unchanged. Date/time labels use the user's locale. Offset-bearing order timestamps use the existing scheduling helper and local zone.

The Dashboard's unpaid invoices alert counts non-cancelled signings whose signing date is before today in the device's local time, Paid is unchecked, and paid date is missing or blank. Today's and future signings are excluded. Tapping the alert opens a searchable list of those same signing records with the existing edit, travel, invoice, and delete actions. Saved order changes update the list and count; the date boundary refreshes every minute while visible. A zero count hides the alert. This follow-up rule does not change the Accounting invoice generator's eligibility rules.

## Assumptions

- The public reference wrapper could be retrieved, but its embedded design could not be rendered (the frame URL returned 404). The written 390×844 specification is the visual source; exact pixel comparison with the artifact remains unavailable.
- The live adapter keeps the existing dashboard's signing-date grouping. Net income is paid signing fees less recorded business-use expenses and parking/tolls for that month. It is not a tax estimate. Prior-month comparison is omitted when the previous net is zero or negative.
- No appointment end times, missing addresses, or live GPS distances are invented. Known trip addresses/one-way miles are reused; Navigate is disabled for missing addresses. The bell counts one alert per saved expired or soon-to-expire commission, E&O insurance policy, background check, or additional credential. Missing, invalid, and later expiration dates do not create alerts. Reading notifications leaves the count unchanged; renewal or removal resolves the alert. A zero count hides the badge.
- The Dashboard offers Signing and Expense quick actions; the Mileage shortcut is hidden while the monthly Mileage statistic remains. Signing and Expense quick actions open the existing creation forms, save through the existing API, and update AppState. The empty next-signing card has no additional Add signing button. Open file and upcoming signings open the selected order's existing Signing Detail screen, with editing and a Done action to return to the Dashboard. Notifications lists credential expiry alerts; each opens the shared credentials editor. See all goes to the existing Signings page. Journal is hidden from the Dashboard actions, Menu, and bottom navigation.
- Greeting text follows the local time of day; the loaded preview uses a fixed morning. The normal 390-point stats layout is 2×2. Very narrow screens and accessibility sizes stack stats; the two quick actions stay in two columns at accessibility sizes, and upcoming date blocks scale with Dynamic Type.

## Validation

The iPhone 15 simulator checks cover model selection, bounded/sorted upcoming data, no duplicate hero, error/retry, canceled and superseded loads, Decimal arithmetic, missing address behavior, Maps URL encoding, and tab ownership. Layout captures cover 320/390/430-point widths in loaded, empty, skeleton, error, and AX3 states, plus a tall AX3 component capture. UI checks exercise all four tabs, placeholder actions, shared subscription access, billing navigation, legal return links, and refresh.

Xcode's AppIntents metadata phase may print its existing skip notice because this app does not link that framework; no AppIntents dependency or warning-suppression setting was added just to hide it.

## Menu tab icon

The Menu tab uses the signed-in user’s profile photo as a circular native tab image. It displays first/last initials while loading, for a missing URL, or after an unavailable/unreadable photo. When name initials are unavailable, the email’s first letter is used, followed by the app initials if no account name/email is available. User/photo changes refresh the icon, and late photo responses from another account are ignored. Photos are downsampled before rendering and no photo URLs or personal details are logged. The profile-photo/initials icon is retained; the tab and menu heading are named Menu.
